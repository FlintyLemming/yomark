# 有码 · 从字面认人名（HanLP）

对 `2026-09-02-yomark-android-design.md` §6 规则表的增补。调研过程见 `docs/on-device-model-research.md`。
第二天的真机反馈把它从单独一条规则并回了「人名」一行，见文末「修订」。

## 起因

滴滴出票页上，乘车人一行是「沐晨冉 成人」，下面是打了星的身份证号。没有字段名，后面跟的也不是电话，
`LabeledField` 和 `NameBeforePhone` 都接不住，只有按需跑的 AI 复查（Gemini Nano）圈了出来。
而 Nano 只在近两年带 GMS 的旗舰上有，随包大模型又太重（最小可用档 1.9 GB、峰值内存 3.8 GB）。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 认法 | HanLP portable 1.8.4 的人名识别（词典加角色标注） | 纯 Java，jar 8 MB，词典预编译在 jar 里，所有设备都能跑；一行零点几毫秒 |
| 许可 | Apache-2.0 | 与本项目其余依赖一致 |
| 挂在哪 | ~~新规则 `name-text`，类型 PERSON_NAME，排在 `name` 后面~~ → **并进 `name`，排在字段名、电话两种锚定之后**，见下方「修订」 | 误报率与锚定的认法差一个量级，默认态必须分开~~、单独关掉~~ |
| 出厂态 | ~~仅圈出（命中带 `outlineOnly`，「人名」选「打码」时也只圈出）~~ → **要旁证**：附近有电话、证件号、地址、「xx人」字段的照「人名」的设置打码，没有的不圈，见文末「修订（2026-10-09）」 | 拿人名、姓氏起头的商号会被认成人名，按 §6「按误报率划线」 |
| 与锚定结果重叠 | ~~不处理，交给合并~~ → 在规则里按先后丢掉 | 锚定的知道名字从哪里开始；一个名字只出一个框 |
| 设置页 | ~~这一行叫「人名（无字段名）」~~ → 只有一行「人名」，下面一行小字~~「凭字面猜出的只圈不打码」~~「没有「姓名」等字段名时，旁边有电话、证件号或地址才认」；页面最下面一个开关「没有旁证的人名也圈出」 | 两行都叫「人名」分不清关的是哪一个 |
| 线程 | 规则判定整体挪到 `Dispatchers.Default` | 调用方是 viewModelScope；第一次分词要等词典读完，留在主线程会卡界面 |
| 预热 | 应用启动时在后台线程读一遍词典 | 第一张图的识别不用等它；读失败也无妨，识别时会再读 |

## 在 HanLP 结果上做的事

- **拼回被切开的名字**：「沐晨」+「冉」→「沐晨冉」；
- **单个的姓往后补**：「陈」+「晓峰」→「陈晓峰」，复姓同理，最多四个字；
- **挡商号**：名字后面紧跟着快递、咖啡、麻辣烫、地图、出行这类行业词的作废；
- **挡地名**：以「路街道巷弄村镇乡区县市省栋幢室号楼」结尾的作废（「祁门路」）；
- **只要中文人名**：音译名（「优衣库」就是被当成音译名认出来的）、日本人名不要。

## 实测

用 `tools/model-eval` 的样本（6 页截图的 OCR 行，设备分辨率）加 128 条界面文字、品牌名、地址：

- 9 个名字全部认出，包括没有字段名的「沐晨冉」「李思雨」、句子里的「周振宇」、只认出姓再补全的「陈晓峰」「赵师傅」；
- 那 6 页与 128 条反例上没有误报；
- 桌面 JVM 上首次读词典约 0.2–0.7 秒，之后每页几毫秒。

## 修订（2026-10-04）：并回一行「人名」

真机反馈：设置页上「人名」和「人名（无字段名）」两行有歧义，分不清关的是哪一个，不如只留一个。

- 规则 `name-text` 撤掉，`PersonNameRecognizer` 并进 `name`，排在 `LabeledField`、`NameBeforePhone` 之后。
  `CompositeRule` 本来就是为「同一类型几种认法、设置页上一行」准备的：后面的认法与前面的结果重叠就丢掉，
  一个名字只出一个区间，不再靠合并去重；
- 默认态的分层留着：从字面认出的命中由 `OutlineOnly` 包一层、带上 `outlineOnly`，`RuleClassifier` 据此
  把它们压成仅圈出。「人名」选「打码」时锚定的打码、字面猜的只圈出，与条码宽松档里解不出内容的疑似条码一个道理。
  设置页这一行名字下面写一行小字「凭字面猜出的只圈不打码」，不然用户会以为打码没生效；
- 一个开关：选「仅圈出」三种认法都只圈出，选「关」三种都不认。代价是不能再单独关掉字面识别，
  也不能让它自动打码。前者的误报只是多一个框、导出时多问一句；后者要的话，导出拦截里点「全部打码」一次盖掉；
- 一种类型一条规则，单测钉住（`OutlinedByDefaultRuleTest`）：同一类型出现两条规则，设置页上就是两行同名的开关；
- 老安装里给 `name-text` 存过的覆盖读回来被忽略，与其他认不出的规则 id 一样；这类名字改由「人名」那一行管。

## 未验证

- 手机上首次读词典的时间与常驻内存（桌面上词典约 30 MB）；
- 真实截图上的误报率。商号、品牌名千变万化，行业词表挡不全，所以出厂只圈不打码；
- 中文识别器逐字切分时（ML Kit 中文档，非默认），「快递员 赵师傅」会认成「员 赵」。
  那一行 `name` 规则按字段名照样认得出赵师傅，合并后多遮一个字。

## 修订（2026-10-09）：逐行看邻居，整页要旁证

真机反馈：淘宝商品规格页（「【成猫单月装】福来恩1支+海乐妙1粒」一类，十几行）被圈满了「人名」——
药名「福来恩」「海乐妙」、规格「成猫」「单月」、「8周以上」里的「周以上」。

### 为什么字面上挡不住

HanLP 的角色标注不看上下文，「姓氏用字 + 一两个字」都可能认成人名。按它自己人名词典里的频次，
「福」作姓 23 次、「沐」18 次，「来」作名首 81 次、「晨」146 次，「恩」作名末 1064 次、「冉」54 次——
**「福来恩」比用户自己的名字「沐晨冉」还像人名**。姓氏表、名用字表这类按字打分的办法分不开它们，只能看周围。

### 逐行：看左右邻居（PersonNameRecognizer）

- 左边紧贴名词、形容词、数量词、代词的不要（「好丽|友派」「8|周」「本|周」）；紧贴的是「司机」「群主」这类身份词可以；
- 右边紧贴名词、数量（「福来恩3支」「冠能猫粮」）或规格字（装套款版型色码味：「单月装」）的不要；
  紧贴称呼、亲属、票种、这个人自己的东西的可以（「张三老师」「沐晨冉成人」「李娜电话多少」）；
- 单个的姓往后补，补上的一两个字得像名（人名词典里作名用十次以上）或是称呼：「陈」+「晓峰」连，「周」+「以上」不连；
- 名要像名：单名那个字作名用不到十次的不要（「猫」4 次、「茗」5 次；「三」22 次、「嵩」41 次、「月」30 次都放过）；
  四个字的只认复姓开头的。

### 整页：要旁证（RuleClassifier + DefaultRuleSet.nameAnchors）

用户提的：人名旁边通常有电话、地址、「xx人」这类字段，没有的十有八九不是人。OCR 给每行（PP-OCR 还给每个字）一个框，
RuleClassifier 一次拿到整页，算得出距离。

| 项 | 决定 |
|---|---|
| 什么算旁证 | 电话（含打星）、邮箱、地址、18 位身份证号（查校验码）、打了星的号码（证件号、卡号）、人名字段名（姓名规则的字段名，加乘车人、入住人、就诊人、抄送、收款方等）、票种（成人、儿童……，要单独成词） |
| 多近算附近 | 同一行（旁证不和名字重叠）；同一排（竖直方向重叠过半，OCR 常把一排拆成几行）；上下相邻（空隙不超过 1.5 个字高、水平错开不超过 2 个字高） |
| 有旁证 | 照「人名」一行的设置：出厂打码。原先一律只圈不打码，滴滴出票页那一行现在直接打码 |
| 没有旁证 | 出厂丢掉，不圈。设置页「文字」最下面加一个开关「没有旁证的人名也圈出」，打开后只圈不打码。「人名」选「关」时这个开关灰掉 |
| 旁证规则被关掉时 | 照样算旁证。关的是「遮电话」，不是「认电话」，与姓名规则拿电话找锚同一个道理 |
| 实现 | `OutlineOnly` 换成 `NeedsAnchor`，`RuleMatch.outlineOnly` 换成 `needsAnchor`；判定挪到 RuleClassifier，旁证只在页面上有猜测时才找 |

### 实测

自拟的 346 行（81 个名字：车票、聊天、转账、物流、病历；288 行反例：那张截图的每一行、宠物药、化妆品、
食品、日化、店名、地名、药名、界面文字），只看逐行这一层：

| | 认出 | 反例行里误圈 |
|---|---|---|
| 修订前 | 79 / 81 | 70 处（55 / 288 行） |
| 逐行看邻居 | 78 / 81 | 5 处（5 / 288 行）：单月、屈臣氏、曲江池、银泰城、奈雪 |
| 对照：百度 LAC（BiGRU-CRF，Apache-2.0，ONNX 约 30 MB） | 79 / 81 | 37 处；加上同样的邻居过滤后 3 处 |

剩下那几处是单独成行的店名、地名，一行之内和通讯录里单独一行的名字没法分，交给整页的旁证：
截图那一页上一个人名都不剩。LAC 加过滤后与 HanLP 差不多，不值得为它再带一个模型，没有换。

**代价**：聊天里随口提到的人名（「转告周振宇周三的会」）、群聊发言人、通讯录里的名字，旁边通常没有旁证，
出厂不再圈出。要的话打开那个开关；有 Gemini Nano 的设备上 AI 复查照旧能补。
自拟样本是看着这些版式写的，数字偏乐观，与上文「未验证」一样，要拿真实截图再量。
