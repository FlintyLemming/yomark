# 有码 · 从字面认人名（HanLP）

对 `2026-09-02-youma-android-design.md` §6 规则表的增补。调研过程见 `docs/on-device-model-research.md`。
第二天的真机反馈把它从单独一条规则并回了「人名」一行，见文末「修订」。

## 起因

滴滴出票页上，乘车人一行是「沐晨冉 成人」，下面是打了星的身份证号。没有字段名，后面跟的也不是电话，
`LabeledField` 和 `NameBeforePhone` 都接不住，只有按需跑的 AI 复查（Gemini Nano）圈了出来。
而 Nano 只在近两年带 GMS 的旗舰上有，随包大模型又太重（最小可用档 1.9 GB、峰值内存 3.8 GB）。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 认法 | HanLP portable 1.8.4 的人名识别（词典加角色标注） | 纯 Java，jar 8 MB，词典预编译在 jar 里，所有设备都能跑；一行零点几毫秒 |
| 许可 | Apache-2.0 | 与本项目其余依赖一致 |
| 挂在哪 | ~~新规则 `name-text`，类型 PERSON_NAME，排在 `name` 后面~~ → **并进 `name`，排在字段名、电话两种锚定之后**，见下方「修订」 | 误报率与锚定的认法差一个量级，默认态必须分开~~、单独关掉~~ |
| 出厂态 | 仅圈出（命中带 `outlineOnly`，「人名」选「打码」时也只圈出） | 拿人名、姓氏起头的商号会被认成人名，按 §6「按误报率划线」 |
| 与锚定结果重叠 | ~~不处理，交给合并~~ → 在规则里按先后丢掉 | 锚定的知道名字从哪里开始；一个名字只出一个框 |
| 设置页 | ~~这一行叫「人名（无字段名）」~~ → 只有一行「人名」，下面一行小字「凭字面猜出的只圈不打码」 | 两行都叫「人名」分不清关的是哪一个 |
| 线程 | 规则判定整体挪到 `Dispatchers.Default` | 调用方是 viewModelScope；第一次分词要等词典读完，留在主线程会卡界面 |
| 预热 | 应用启动时在后台线程读一遍词典 | 第一张图的识别不用等它；读失败也无妨，识别时会再读 |

## 在 HanLP 结果上做的事

- **拼回被切开的名字**：「沐晨」+「冉」→「沐晨冉」；
- **单个的姓往后补**：「陈」+「晓峰」→「陈晓峰」，复姓同理，最多四个字；
- **挡商号**：名字后面紧跟着快递、咖啡、麻辣烫、地图、出行这类行业词的作废；
- **挡地名**：以「路街道巷弄村镇乡区县市省栋幢室号楼」结尾的作废（「祁门路」）；
- **只要中文人名**：音译名（「优衣库」就是被当成音译名认出来的）、日本人名不要。

## 实测

用 `tools/model-eval` 的样本（6 页截图的 OCR 行，设备分辨率）加 128 条界面文字、品牌名、地址：

- 9 个名字全部认出，包括没有字段名的「沐晨冉」「李思雨」、句子里的「周振宇」、只认出姓再补全的「陈晓峰」「赵师傅」；
- 那 6 页与 128 条反例上没有误报；
- 桌面 JVM 上首次读词典约 0.2–0.7 秒，之后每页几毫秒。

## 修订（2026-10-04）：并回一行「人名」

真机反馈：设置页上「人名」和「人名（无字段名）」两行有歧义，分不清关的是哪一个，不如只留一个。

- 规则 `name-text` 撤掉，`PersonNameRecognizer` 并进 `name`，排在 `LabeledField`、`NameBeforePhone` 之后。
  `CompositeRule` 本来就是为「同一类型几种认法、设置页上一行」准备的：后面的认法与前面的结果重叠就丢掉，
  一个名字只出一个区间，不再靠合并去重；
- 默认态的分层留着：从字面认出的命中由 `OutlineOnly` 包一层、带上 `outlineOnly`，`RuleClassifier` 据此
  把它们压成仅圈出。「人名」选「打码」时锚定的打码、字面猜的只圈出，与条码宽松档里解不出内容的疑似条码一个道理。
  设置页这一行名字下面写一行小字「凭字面猜出的只圈不打码」，不然用户会以为打码没生效；
- 一个开关：选「仅圈出」三种认法都只圈出，选「关」三种都不认。代价是不能再单独关掉字面识别，
  也不能让它自动打码。前者的误报只是多一个框、导出时多问一句；后者要的话，导出拦截里点「全部打码」一次盖掉；
- 一种类型一条规则，单测钉住（`OutlinedByDefaultRuleTest`）：同一类型出现两条规则，设置页上就是两行同名的开关；
- 老安装里给 `name-text` 存过的覆盖读回来被忽略，与其他认不出的规则 id 一样；这类名字改由「人名」那一行管。

## 未验证

- 手机上首次读词典的时间与常驻内存（桌面上词典约 30 MB）；
- 真实截图上的误报率。商号、品牌名千变万化，行业词表挡不全，所以出厂只圈不打码；
- 中文识别器逐字切分时（ML Kit 中文档，非默认），「快递员 赵师傅」会认成「员 赵」。
  那一行 `name` 规则按字段名照样认得出赵师傅，合并后多遮一个字。
