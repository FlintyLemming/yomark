# 有码 · 编辑器反馈增补（天蓝色块、扫光与落码）

对 `2026-09-02-youma-android-design.md` §7.2、§8 的增补。起因是装上 PP-OCR 版之后的真机反馈；
同一轮反馈里「Gemini Nano 复查改为按需」见 `2026-09-30-youma-ppocr-gemini-nano-design.md` 的「修订」一节。
第二轮反馈撤回了块内类型名、重做了扫描动效，见文末「修订」；第三轮加了一种可在设置里切换的磨砂动效，见「修订（第三轮）」。

## 实色块改为天蓝色

`MaskOptions.solidColor` 出厂值从黑改为天蓝 `#87CEEB`（`MaskOptions.SKY_BLUE`）。

- 预览与导出同色。所见即所得不为颜色破例，导出图上也是天蓝色块；手动框同色，导出图里不会黑蓝混杂。
- 安全性不变：`SolidRenderer` 仍强制不透明。像素化区域太小、抹除遇到复杂背景时降级成的实色块随之变成天蓝色。
- 从重建里恢复的会话沿用它 plan 里存着的颜色，不改写。

## 识别中的扫光与结果上屏的落码

PP-OCR 一张图约两秒。这两秒里画面不动，用户会以为卡住了；结果上屏那一下，用户又该看清哪些地方被打了码、原来是什么。

**识别中：扫光。** 页面不压暗、不画线。一束柔光自上而下扫过：

- 光下的字被染上颜色，白底不变——先**滤色**（90%）叠一层光，白色滤色之后还是白；再正常叠一层 22% 的淡光晕，空白处也看得见光走到了哪里。看上去是光在逐行读这一页；
- 颜色是天蓝 `#87CEEB`（与打码块同色）→ 长春花蓝 `#A5B4FC` → 淡紫 `#C4B5FD`，左右缓缓流动，3.2 秒一个周期；
- 形状：中心往上拖 150 dp 的长尾、往下 36 dp 的前沿，两端平滑落到 0。读得出方向，用不着一条硬边；
- 一趟 2 秒，匀速里掺一半正弦缓动，起止柔和。每一趟都从图像上方整道光藏着的位置出发、到下方完全离开为止，跳回顶部那一下看不见。识别开始时 0.32 秒淡入；
- 只画在图像范围内，不碰画布留白；
- 顶部提示条「正在识别敏感信息…」去掉了转圈的进度圈，换成同色的一道光从字面掠过（1.6 秒一次），和图上那束光是一回事。

**结果到达：落码。** 还在半路的那道光 0.24 秒内退场，光从顶部再扫最后一遍（1.4 秒）：

- 打码块与圈出框紧跟在光的后面自上而下显现：光的中心以下还没有，中心往上 110 dp 处盖实，中间渐变；
- 块还半透明的时候正被光照着——用户看得见底下原来是什么，再看着它被盖实。这一下替代了块内的类型名；
- 走完时光尾和渐显区都已离开图像，换回静止画法时画面不跳。

**不变的：**

- 换方案重跑时，旧的识别结果在扫光期间先退场；手动框始终显示，浮在光上面；
- 从重建里恢复的 plan 直接显示，不再演一遍；
- 只是编辑器里的过渡：不改 plan、不进撤销栈、不进导出。识别期间画布照常可交互，提示条不吃触摸；
- 时间轴只在绘制阶段读取，动起来只触发重绘；识别中和落码那一遍之外一帧都不占。

**实现：** 时长、轨迹、光形与渐显全是 `ScanEffect` 里的纯函数（单测）。画布上除选中态与草稿框以外的内容拆成
`drawScene`，像素测试直接画出任意一帧。落码只用一个离屏图层，再拿一道竖直渐变（DST_IN）只留光走过的部分，
不再每块一个图层。

## 修订（2026-10-01，第二轮）：撤回块内类型名，扫描动效重做

第二轮真机反馈两条：

1. 扫描动效「有点土」。上一版是 16% 的暗幕加一道天蓝硬亮线、带拖尾，反复扫——扫码枪和手机管家「病毒扫描」的样子；
2. 已打码块里的类型名不要了。当初想要的其实是让用户知道默认打码的地方原来是什么内容；用户提议换成给打码加一个自上而下的渐显。

处理：

- 块内类型名整个撤掉（`MaskedLabel` 删除），已打码的外观回到 §7.2 原文「实心遮罩（当前样式）」。圈出项的琥珀色小标签不变；
- 「原来是什么」交给落码：块是在原文上从半透明慢慢盖实的，盖实之前底下的字看得见。上一版的淡入只有 0.65 秒、
  逐块整体变透明，几乎注意不到；
- 扫描动效重做为上面的扫光。

试过、没采用：

- **磨砂**（整页模糊，光扫过处变清晰，落码时磨砂自上而下褪去）：画面最有冲击力，但打码块会直接从「糊」变成「盖住」，
  底下原来是什么用户一眼都看不到，正好违背这一轮的目的；识别期间画布可交互，糊着也不好下手画手动框；
- **暗幕 / 白纱**：白底截图上压暗显脏，压白像禁用态；
- **光里撒星点**：白底上看不见，深色图上又显得花。

## 修订（2026-10-06，第三轮）：磨砂动效，设置里切换

第三轮反馈：想要 Android 原生那种「带一点光点杂质的闪烁模糊」的等待效果，中间放一个边转边变形的等待图标，
识别完从中心散开；与扫光两种在设置里切换。

**来源。** 描述对得上的是原生壁纸选择器生成壁纸时的加载动效（AOSP WallpaperPicker2 的 `LoadingAnimation`）：
重度模糊（半径 80 dp）、一层深色滤色、随 simplex 噪声成片漂移的光点（SystemUI 着色器库的 `sparkles()`，
一个个 0.8 dp 的小格按各自的节奏明灭），加载完一个圆从屏幕中心向外把它揭开。等待图标是 Material 3 Expressive 的
`LoadingIndicator`：七个形状（柔和十角星、九瓣曲奇、五边形、药丸、八角太阳、四瓣曲奇、椭圆）首尾相接地变形，
每 650 ms 一次，用阻尼 0.6、刚度 200 的弹簧走完，同时顺时针转四分之一圈；整体再匀速转，4.666 秒一圈。

**原样搬过来不成立，改了什么。** 上一轮否掉「磨砂」和「光里撒星点」的理由，这一版各有对应：

- 白底上看不见：原版的深色是滤色，白底滤色之后还是白；光点是加上去的，加在白上也看不见。用原版着色器的算法在样图上
  模拟过，整页只剩一张发白的毛玻璃。这里改成压一层深蓝（50%），白底变灰蓝，光点和图标才显得出来；模糊只用 σ 10 dp
  （原版约 46 dp），卡片和文字行还认得出形状，看得出是「这一页正在被处理」；
- 「打码块直接从糊变成盖住，底下原来是什么看不到」：散开时洞里是清晰的原图，打码块在洞的边缘后面 110 dp 内才盖实，
  与扫光的落码一样，先看得见原来是什么，再看着它被盖住；
- 糊着不好画手动框：仍然成立，所以磨砂不是出厂默认，由用户自己选。手动框照常显示，清楚地浮在磨砂上面。

**识别中：**

- 模糊图与原图交叉淡入（0.6 秒，先快后慢），深蓝压暗一起上来；
- 一层很淡的天蓝 / 淡紫云随噪声起伏（滤色 32%），只在噪声高的地方浓；
- 光点照搬原版的 `sparkles()` 与噪声遮罩：噪声低的地方成片出现、随噪声漂移，每个点按自己的节奏明灭。云和光点各占一片；
- 画布中心是 48 dp 的等待图标（淡天蓝），入场时由 0.6 倍放大淡入。图标跟屏幕走，不随图缩放平移。

**结果到达：散开。**

- 等待图标 0.28 秒内放大到 1.5 倍淡出；一个洞从它底下长出来，1 秒内长到盖过最远的角（半径一半匀速、一半先慢后快再慢）；
- 洞的边缘柔化 20 dp（原版是硬边，像开了一扇圆窗；柔一些才像雾从中间化开），边上一圈光点不看噪声、一律亮起来，
  像磨砂在边上化成了光；
- 识别出的块在洞的边缘后面 110 dp 内由透明到盖实；
- 圆心是结果到达那一刻的画布中心（图标所在的位置），换算成图像坐标，之后拖动画面，洞跟着图走；
- 识别快过淡入时，磨砂停在那一刻的浓度，洞外剩下的那一圈不再变浓。

**设置。** 识别设置一级页的最后一项「识别动效」：扫光（出厂）/ 磨砂。存在 DataStore 的 `scan_style` 里，
不进 `RecognitionConfig`——换它不重跑识别。「全部恢复默认」把它一并恢复成扫光。识别中跟着设置走，
结果到达那一刻定下来，收尾那一遍不再变。

**实现：**

- 不用 AGSL：最低支持 Android 10，`RuntimeShader` 要 Android 13。全部用 Canvas 画，Robolectric 上能直接画出任意一帧做像素测试；
- 模糊：识别开始时在后台把分析图逐级对半缩小，缩到模糊半径只剩两三个像素，再做三遍盒式模糊（约等于高斯），画的时候拉伸回去；
- 噪声：照搬原版的 `simplex3d`（连同它的整数哈希），只在 16 dp 一格的网格上算；云直接拿这张网格做一张小位图拉伸上去，
  光点的遮罩从网格上双线性插值；
- 光点：原版逐个 0.8 dp 的像素格算；这里在准备阶段按 1.4 dp 一格挑出会亮的格子（约 7%，一屏约一万个），每帧只算它们的明灭，
  按亮度分六档，每档一次 `drawPoints`；
- 等待图标：Material 3 的 `LoadingIndicator` 目前只在 compose-material3 1.5 的 alpha 里，不为它升级到 alpha 版。
  用它底下那套稳定的形状库 `androidx.graphics:graphics-shapes` 照原样画，形状数值取自 `MaterialShapes`。
  画在画布上而不是另放一个组件：与磨砂同一根时间轴，结果到达时才能和那个洞严丝合缝地接上；
- 散开时磨砂画进只有图像大小的离屏图层，再用径向渐变（DST_OUT）挖洞；识别出的块画进另一个离屏图层，
  用径向渐变（DST_IN）只留洞里的部分；
- 时长、轨迹是 `FrostEffect` 里的纯函数，噪声与光点在 `FrostNoise`，都有单测；像素测试见 `FrostSceneDrawTest`。

## 未验证

- 扫光与落码在低端机上的帧率。识别中每帧两个渐变矩形（滤色 + 正常叠加）；落码那 1.4 秒里多一个整画布的离屏图层，
  所有识别出的块每帧重画一遍（模糊样式最重）；
- 扫光只在测试截图（白底）和合成的黑白条纹上看过渲染结果，深色照片、强光下的观感还没上真机看；
- 磨砂在低端机上的帧率：识别中每帧在 CPU 上算一千来次噪声和约一万个光点的明灭，散开那 1 秒里多两个离屏图层；
- 磨砂同样只在样图（白底截图）上看过渲染结果；等待图标的颜色固定为淡天蓝，没有跟随系统的动态取色。
