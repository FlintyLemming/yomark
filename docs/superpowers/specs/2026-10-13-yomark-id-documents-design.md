# 有码 · 证件：方向、号码、字段与水印

对 `2026-09-02-yomark-android-design.md` §6 规则表、§5 识别流程的增补。各国证件号码的格式、校验位和样例的调研不进仓库，
结论都落在了规则的注释和单测里。

## 起因

用户发来两张 0.15.0 编辑器的截图，都是身份证人像面竖着放、拍歪了的照片：

- 第一张：PP-OCR 按图上的横竖读，把一列列字串成了一行（「住 址 … 出 生 … 姓 名 …」），规则遮的是一串不相干的字；
- 第二张转正后再读：字段名读坏了（「姓」读丢，「性别」读成「性新」），年份里夹着空格，号码中间补了空格、头一位粘在「码」上。
  姓名、出生、号码一处都没遮；号码即使读整齐了也只圈成「长数字串」，过了 Luhn 的还标成「银行卡号」。

顺着查下去：身份证住址折到第二行的只遮了门牌；驾驶证上字段名和值隔着大半栏，OCR 拆成两段，姓名、住址都没遮；
复印件上斜着平铺的水印把压住的字和水印检测成一块，出生日期、住址读丢了。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 新类型 | 证件号码（`ID_NUMBER`，规则 `idnumber`）、车架号（`VIN`，规则 `vin`），都默认打码 | 没字段名的要过校验位，有字段名的字段名就说明了是什么，误报都少（§6 按误报率划线） |
| 证件号码认什么 | 大陆身份证号（地区码、生日、校验码，OCR 补的空格也认）、香港、台湾、新加坡、韩国、马来西亚身份证号、日本在留卡、巴西 CPF；字段名后面的号码不验校验位；往来港澳台通行证、回乡证、台胞证的机读码 | 字段名后面的号码 OCR 认错一两位照样该遮；跟在「订单号」「办件编号」后面（同一行、左边一栏、正上方）、只靠形状认的不算；台湾、新加坡、马来西亚、日本和没有校验位的韩国号码要页上写着是哪儿的证件 |
| 护照 | 护照的机读码、护照号仍归护照，通行证的归证件号码 | 设置页上「护照」一行只管护照 |
| 银行卡 | 卡号之外，大写字段名后面的安全码（CVV2、CVC）和有效期（VALID THRU 12/28）也归银行卡号；有效期要页上有卡 | 中文的「有效期至」到处都是（优惠券），不认；优惠券上也印「VALID THRU」 |
| 字段名 | 证件号码、车架号与姓名、地址、出生日期共用一套认法（`LabeledField`） | 字段名读散了、带英文译名、值在右边一栏，几类一起受益 |
| 证件上的姓名、住址、出生日期 | 字段名读坏了的身份证人像面按排版认，住址折行接着遮，生日拿身份证号对，毕业证按句子认 | 见下文「规则」 |
| 方向 | 竖着、倒着、拍歪了的页转正了读；规则在阅读方向上看版面；人脸转正了再找一遍 | 见下文「方向」 |
| 水印 | 斜框压住的那排字横着切出来重读 | 见下文「水印」 |
| 车牌 | 不在这里做，只理顺两边同处一页的时候 | 车牌那一支（`LICENSE_PLATE`、规则 `plate`）已经并进 main，行驶证上的「号牌号码」归它认；同处一页见下文「和车牌」 |

规则表因此是 20 条（含车牌）：15 条默认打码、5 条仅圈出。设置 › 文字里证件号码排在取件码后面、车牌前面，车架号在护照后面。

## 方向

- **OCR 转正了读**（`TextAxis`、`PpOcrEngine.readTurned`）：先在原图上检测，按检测框的长边估出行的走向（众数附近求平均）。
  竖着、歪着的转到行横平的方向上读，差半圈的两个方向问识别器自己哪个读得更有把握；横平的读得磕绊（平均置信度不到 0.8）才试倒过来。
  不重新检测，框逐点转到画布上再转回原图；
- **防带歪**：横平竖直的行占到总长的四分之一就按横平竖直读（斜着平铺的水印往往比证件上的字还长），
  歪着的页上另有一组斜行占到四分之一也不转；
- **规则在阅读方向上排版**（`ReadingFrame`）：`RuleClassifier` 把每个框转到阅读方向的坐标系里再交给规则，
  「下面一行」「同一排右边」「左对齐」在竖着的图上照样成立。候选的框仍是图上的；
- **合并**（`CandidateMerger`）也按阅读方向算「同一行」：竖着的图上上下两行地址是左右挨着的两列，不再拼成一大块；
  候选带着各自的方向（`Candidate.readingDegrees`），截图里转过的证件照、车的照片上的只和同一个方向的合并，叠在一起的才跨方向合并；
- **小照片**：截图里一张转过、拍歪了的车的照片字少，不单分一组；方向和那一组差 5° 以上的行按它自己的方向量（`Page.boxIn`），
  上下两行、孤零零一行的车牌照样认得出。两行的牌子按下一行、上一行、这一页的方向各试一遍：短行的框方向时准时不准，差一两度就过了门槛；
- **人脸**：页面转了直角的，ML Kit 在转正的图上再找一遍，框转回原图。

## 规则

### 证件号码、车架号

- 身份证号连起来正好 18 位的几段数字（段与段之间单个空格）算一个号码，只在段与段之间切；X 认 x、×、全角和希腊、西里尔字母里长得一样的；
- 字段名一组一种认法，值的形状各自卡：「FIN」「NRIC」要新加坡的形状，「ID No.」前面紧挨着别的英文词的（「Tracking ID Number」）不算，
  「統一編號」要个人的、「证书编号」要数字打头的；值最多 20 个字母数字，超了从空格处截（后面那段常是手机号）；
- 号码在同一排右边另成一段的（驾驶证「证号」和号码隔着大半栏）也接：证件号的形状够严，表头的下一格、「未填写 >」、打了星的都对不上；
- 车架号：字段名后面的 17 位不验校验位；没有字段名的要第九位校验位对得上、至少两个字母、最后四位是数字。

### 字段名

- 汉字字段名的字与字之间可以夹空格（「公民 身份号 码」「住　　所」）；
- 后面的英文译名跳过去再取值（「姓名 Name」「证件号码/Card No.」「车辆识别代号(VIN)」）：七个字母以上的差一个字母也认（「Narne」「Adress」），
  缩写只认大写（「姓名 Vin Diesel」里的 Vin 是名字），两个字母的「No.」要带句点（「NO」是个姓）；
- 中文字段名带着译名、单独成一段的，值在同一排右边一段（驾驶证、行驶证的版式）；
- 也是常用词的字段名（「所有人」「法定代表人」「住所」「出生地」）后面要隔着空格、冒号或译名，值还要像个名字、不以「是」「在」打头。

### 证件上的姓名、住址、出生日期

- 住址折到下面不带字段名的几行（`FollowingLines`）：和值左对齐、紧挨着、有门牌地名用字、不以字段名打头；
  截图里拍歪了的证件照（字少，不单分一组），值那一行、下面那几行有自己的方向的，也按它们的方向量，量出来的框要不比按整页量的高；
  读错了的英文译名算进了值（「住址 Aaaress 江苏省…」），下一行对着它后面的汉字；
- 身份证人像面字段名读坏了的（`IdCardFront`）：先认出这是人像面（性别民族那一行，或「公民身份号码」加出生那一行），再按死的行序取姓名、住址；
- 身份证号里的生日在页上别处出现，那一处就是出生日期（`IdBirthEcho`），「出生」读丢了也遮得上；
- 出生日期认只写到月的、民国和日本年号的；毕业证「张三，男，……生」里的名字和日期；通行证上名字下面的拼音。

## 水印

DB 把斜着平铺的水印和它压住的字连成一块，框是斜的，字跟着水印读成了字母；中文水印斜二十几度时，
「浙江省杭州市西湖区文三路」和压着它的「仅供办理银行开户使用」连成一个斜 9° 的框，什么都读不出来。识别器隔着浅色的水印却读得出横着的字：

- 页上有斜框时，斜框穿过的每一排横平的字横着切出来重读：两段之间的空当被斜框盖住的整排重读，两头被盖住的往外接，
  接到墨色深过水印的字为止（墨色按这一排自己的字量）；同一排被隔开的两截接到一起的并成一截读；
- 横平的框斜了 6° 以上的当斜框（字和水印连成的一块）；
- 水印密、比证件上的字还长时，整页按水印的走向读，证件上的字在原图上读，这些行同样重读；
- 重读的要留住原先读出的八成字（压着水印的单字原先常读错，「出」读成「山」），才换掉原先那几段；
- 两个框走向差 15° 以上的不拼成一行，水印的字母不再串进证件的行里；
- 没有斜框的页一个框都不多读。

## 实测

合成的身份证、驾驶证（`tools/test-images/`，内容全是编的），真模型、出厂规则表，从像素到打码（`IdDocumentOcrTest`）：

| 图 | 打码 | 只圈出 |
|---|---|---|
| 身份证人像面，正着、转 90°/180°/270° | 姓名、出生日期、两行住址、证件号码，正好这五处 | 无 |
| 竖着放、拍歪 4° 的照片 | 同上 | 无 |
| 压着浅色英文水印、密铺灰色中文水印 | 同上（水印那一行里读出的名字也打码，和名字叠在一起） | 无 |
| 国徽面 | 无 | 有效期限的两个日期 |
| 驾驶证，正着、转 90° | 姓名、出生日期、两行住址、证号（证件号码） | 初次领证、有效期限的三个日期 |

- 0.15.0 上同样这些图：身份证号只圈成长数字串，住址第二行只遮了一半（「6幢2单元501 室」）；转 90° 的读成一列列，倒着的是乱码；
  驾驶证的姓名、住址第一行没遮；
- 水印重读之前（方向和两个规则分支都已合入）：英文水印那张出生日期没遮、住址框盖住了半张卡；中文水印那张只遮了住址第二行；
- 用户那两张照片（只在本机复现，不进仓库）：姓名、出生日期都打码，读得出来的住址、号码也打码；
- 47 张图（测试图、README 和 Play 的截图、评审时合成的证件）水印重读前后对照：39 张一字不差，变了的 8 张都压着水印。
  6 张证件多遮上了出生日期、住址、号码里的一到三样；一张拿物流页的字当水印铺在证件上的，只是地址框变了；
  Play 第 6 张截图（「仅供快递理赔使用」）水印不再串进界面的行里，认出的东西不变；
- 桌面 JVM 上识别一张证件 0.1–0.2 秒，转了直角的和正着的差不多；压着水印的多读几排，0.16→0.20 秒（英文）、0.20→0.28 秒（中文）。
  规则判定每页几毫秒；
- 规则在证件版式上（`IdDocumentPageTest`、`IdNumberPageTest`）与在聊天、订单、合同、设置页上不该认出什么（`IdRulesOnOrdinaryTextTest`、
  `IdNumberFalsePositiveTest`）都钉成了单测；证件版式整页转 90°/180°/270°/94°/−3.5° 认出的和正着的一样（`RotatedPageRuleTest`）。

## 第二轮评审

误报、证件覆盖、转向实拍、代码四路评审之后改的（例子都钉成了单测）：

- **单据号**：没有字段名的号码，字段名在左边一栏、正上方一行的也算跟在提示词后面（支付宝账单、政务办件详情）；号码里的「生日」在一年以内的不当身份证号；
  车架号的厂商代码后面要有字母（「DD202610131530014」这种字母前缀加数字的单据号过得了校验位）；
  台湾、新加坡、马来西亚、日本的号码要页上的提示词（12306 的订单号「E875196458」过得了台湾身份证的校验）；
  「户号」要户口簿上的字，「证书编号」要个人证书上的字；
- **字段名**：斜杠、竖线后面又跟着冒号的是第二个字段名（「签收人/签收时间：」）；四个字以上的字段名前面挨着汉字也认（「户别家庭户户主姓名张三」）；
  「住所」「营业场所」后面要有省市区县、路、号或数字；繁体、英文界面的提示语不是值；
  英文小字读错了两三个字母的（「姓 名 tame」）当译名，接右边一栏的值；右边一栏挑和字一样高的，不挑斜着压过来的水印；
- **证件**：名字中间空格不匀的（「王小 明」）、间隔点读成「-」「。」的整个遮；港澳台居民居住证只有「性别」一行也认人像面；
  香港身份证上没有字段名的中文名、英文名、电码；户口簿的「……由……迁来」；台湾证件的全角数字；
- **方向**：众数是斜着的水印、横竖附近的行不只零星几行的，按横竖那一组转（竖着、倒着拍的压着中文水印的证件）；
  截图里转过的证件：竖着的一组不少就转过来读，竖着的几列不再拼成一行，正着的页上读得磕绊的一组横框倒过来试，
  规则按走向分组各认各的（`RuleClassifier`）；拍歪了几度的证件，拼行时按它自己的走向量「同一排」。

## 和车牌

- 同一行的地址和车牌（地址取到行尾）：地址截到车牌前面，夹在中间的车牌字段名不遮，别的字段名跟着冒号的（「车辆：」「车位：」「Vehicle:」）也不遮；
  截完只剩一个字、车牌占了大半的（「苏A12345D」像爱尔兰邮编）才整个让给车牌；
- 车牌字段名（「号牌号码」「车牌号」「车牌」）是下一个字段：名字、出生地到它为止，住址折行到它为止，空着的「姓名 Name」不接它那一栏；
- 车架号、证件号里像车牌的一段（OCR 在车架号中间补了空格的「LFV2A21 K6D4123456」）让给车架号、证件号；
- 行驶证、驾驶证副页的「档案编号 File No.」归证件号码；「车主姓名」「车主」是人名字段名。「车主」和值之间只隔着空格时，值不能整个是个寻常词
  （车主 app 上的「车主 福利」「车主 余额」，「所有人」「负责人」同样）；
- 车牌不当从字面猜出的人名的旁证：停车、ETC、违章页上挨着车牌的是停车场、地名、店名（「万象城」「汤山」「杨国福」），猜出来也像人名；
- 照片上欧盟蓝条的国别字母粘在号码上（「PAB-123-CD」）：整行就是这块牌、附近又没有别的字（同孤零零一行的牌）时去掉它再认，打码。
  截图、规格表里去掉头一个字母像法国牌的型号（「HDX-500-WH」「DHL-123-AB」）上下总挨着别的字，不认；只有这一行的图和一张车的照片分不开。

## 截图里的照片（OCR）

- 两张照片转的方向相反（一张 90°、一张 270°），或者一张倒着、一张转 90°：竖着的框不分朝哪边读，整页只挑一个方向转正，
  另一张是倒着的。画布上、原图上读的两拨里都再找倒着的一组，倒过来读（`PpOcrEngine.readTurned`）；
- 字多的截图下面一张倒着的照片：读得磕绊的横框按挨得近不近分堆，占比按那一堆围起来的那块算，倒过来读得更好的那一组再往外一圈圈接
  读错了却读得有把握的（「AB-23-CD」）；
- 拍歪了十几二十度的照片：过了 15° 的斜框以前一律当水印。挨在一起、走向一致（差不到 6°）、中间几乎没有横平的字（横框不到斜框总长的一成）
  的一片斜框当一张照片：不拿它重读旁边的字，拼行按它自己的走向（实测水印压着的证件，横平的字占斜框两成半以上、走向差十几度以上）；
- 92 张图（评审合成的截图、测试图）改前改后对照：67 张一字不差，变了的 25 张都是照片转过、倒着、歪着的，只多认出、不少认。

## 未验证

- 真实的证件照片只有用户那两张；水印的门槛（斜 6° 算连成一块、墨色走四成、留住八成）是在合成图上定的；
- 水印的颜色和证件上的字一样深时，往外接会接进水印的字里，那一排多出几个字（多遮，不会少遮）；
- 一张截图里正着的字旁边斜放着一张照片：只有一行斜着的字、走向不齐、或者中间夹着不少横平的字的，仍当水印，可能接进旁边那一排；
- 手机上压着水印的页多花的时间；
- 已知的小毛病：单独一行的「IP 地址 192.168.1.5」当地址；「ID No. 12345678 2026」把年份一起遮；
  只有一行的「本协议自2026年9月3日生」当出生日期；压着水印的卡上，水印那一行里也读出了名字，和卡上的名字并成一个框，多盖住一个「名」字；
- 水印把字整个吞了的（转 90° 时的名字）、截图里的银行卡持卡人拼音、日文假名的名字、澳门身份证上下排的号码，还认不出；
