# 有码 · 实验室：外部模型做 AI 增强识别

对 `2026-09-30-yomark-ppocr-gemini-nano-design.md` 的增补：「AI 增强识别」除了本机的 Gemini Nano，
还可以接一个用户自己配置的外部大模型（OpenAI 兼容的 Chat Completions 接口）。

> **2026-10-18 删掉**：上架要声明没有联网权限，这个功能整个去掉了，`INTERNET` 照旧在合并阶段摘掉、不进权限白名单。
> 0.18.0 起填过的开关、接口地址、API Key、模型，升级后头一回读设置时清掉（`SettingsStore.kt` 的 `DropExternalModel`）。
> 下面的调研留作记录；「相邻两行拼起来找原文」那一条对 Nano 也有用，留下了（`SemanticPrompt.acrossLines`）。

## 起因

Gemini Nano 只有近两年带 GMS 的旗舰上有，召回也有限：同一套提示词在 55 页标注（`tools/model-eval/nano-pages-zh.json`）上
Nano 认出约三分之二。用户决定**去掉「应用不联网」这条要求**，让 AI 增强识别可以改用外部模型，功能放进实验室。

## 调研结论（2026-10-15，glm-5.3-flash）

四种接法都量过，脚本没有进仓库：

| 接法 | 结果 |
|---|---|
| **PP-OCR 的文字给模型**（同 Nano，提示词、解析原样） | 55 页召回 **89%（502/563）**，误打 1 处，每页中位 2 秒；33 张聊天截图上 98% 的名字、群名盖住一半以上 |
| 只给截图，模型自己给框（0–1000 归一化 / 像素） | 只有 14% / 34% 的框盖住一半以上；框上下漂 10–20 像素，一半落不到任何一行字上 |
| 截图给模型，回原文，由 PP-OCR 定位 | 和只给文字一样，不多认出一处；输入 token 翻倍，整张图发出去；模型看图读对、OCR 读错时原文落不到字上 |
| 截图加文字 | 同上 |

所以：**只发文字，原文由 PP-OCR 的字级框定位**（`SemanticPrompt.locateAll`，Nano 一直就是这么做的）。
多模态模型给的框不能直接当码用；人脸、条码、头像这些不是字的，本来就由 ML Kit 和聊天版面那一层认。

另两条：

- **规则认出的号码先换成占位符再发**（`〔电话〕`、`〔证件号〕`）：人名、昵称、群名、地址的召回 88.2%，不换是 85.9%，没有变差，
  这些号码也就不离开手机；
- **请求带 `reasoning_effort: "low"`**：不带时一次想几千 token，几十秒到两分钟；`enable_thinking: false` 关不干净，推理的话会混进回答里。

## 决定

| 项 | 决定 | 理由 |
|---|---|---|
| 网络 | manifest 里留下 `INTERNET`，`ACCESS_NETWORK_STATE` 照旧摘掉；构建断言白名单加 `INTERNET` | 外部模型要联网；系统层面没法在运行时关掉这条权限 |
| ML Kit 遥测 | 摘掉 `TransportBackendDiscovery` 上的 `backend:…CctBackendFactory` | 原先靠没有 `INTERNET` 挡住它；有了网络权限它会往 Google 回传使用统计，跟用户开不开外部模型无关 |
| 开关 | 设置 › 实验室 › 外部模型，出厂关着 | 实验性；会把文字发出手机 |
| 配置在哪 | 开关打开后，设置 › AI 页多出「外部模型」一组：接口地址、API Key、模型、测试连接 | 用户要求 |
| 存哪 | `SettingsStore` 里四个键，不进 `RecognitionConfig` | 进了的话改一个字编辑器就重跑整张图的识别；`allowBackup="false"`，key 不进备份 |
| 和 Nano 的关系 | 开着、填好了接口地址和模型：AI 增强识别用外部模型，Nano 让开；没填好：照旧用 Nano | 用户打开实验室开关就是要换模型；两个都跑要等两遍 |
| 总开关 | 仍是「文字」页的「AI 增强识别」 | 外部模型只是它的另一个后端 |
| 何时发请求 | 只在用户点编辑器里的「AI 增强识别」时，和测试连接时 | 与 Nano 同；进编辑器、识别都不联网 |
| 发什么 | OCR 的文字（同 Nano 的筛法），规则认出的号码先换成占位符 | 见上 |
| 一次发多少 | 一段 6000 字，一页通常一次发完 | 没有 Nano 的 4000 token 上限 |
| 请求体 | `model`、`messages`、`temperature: 0`、`reasoning_effort: "low"`；回 400 时只带 `model`、`messages` 再发一次 | 有的接口不认后两项 |
| 回答 | `choices[0].message.content`，去掉 `<think>…</think>` 再按「类型\|原文」解析 | 有的推理模型把思考写在正文里 |
| 超时 | 连接 10 秒、读 30 秒，一段最多等 45 秒；超时、连不上、接口报错都算「没跑成」，编辑器说「识别失败，重试」 | 实测中位 2 秒、p90 约 11 秒；不能让用户以为这一页被看过了 |
| 只接 https | 是（Android 默认不许明文） | 接口地址里带着 key |

## 解析的一处改动（Nano 也受益）

原文在单行里找不到时，再在**相邻两行拼起来**的文字里找，跨行的那一处拆成两段，各落在自己那一行上。
OCR 把地址拆成两行（证件上的住址、聊天里换行的「…5幢302」「室」）时，原先每种模型都打不上码。

## 编辑器

「AI 增强识别」按钮出不出现，仍由 `RedactionEngine.refineReady()` 探测（外部模型只看配置填没填好，不联网）。
外部模型的设置变了（开关、接口），编辑器不重跑识别，只重新探测一次：变得可用就把按钮摆出来，
已经跑过（`Done`）的也重新可点——换了模型，结果可能不一样。

## 不做

- 看图（多模态）：见上表，没有收益；
- 明文 http（局域网里自己架的模型）：要放开 cleartext，以后有需要再说；
- 把 key 加密存：应用私有目录、不备份，和 DataStore 里别的设置一样。

## 未验证

- 真机上的耗时（测的是桌面网络）；
- 别家接口（OpenAI、DeepSeek、通义等）对 `reasoning_effort` 的处理，靠 400 重发兜底。
